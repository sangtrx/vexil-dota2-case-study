# Team/league dependence: post-TEST scientific stress audit

**Status: NON-SELECTING, POST-HOC.** This is an audit of the **unchanged** 500-game cohort and the **unchanged** 3,836 held-out predictions. It cannot create a second blind TEST, prove the time interaction adds value, rescue an invalid confidence interval, or justify tuning/promoting M1. Keep the preregistered original whole-match bootstrap as the primary reported uncertainty.

## Research question

*Are the 106 TEST matches sufficiently independent to trust a confidence interval constructed by resampling entire matches?* The original split is chronological and series-disjoint, but teams play in multiple series and leagues. Different series may therefore share form, strategies, schedules or patch conditions. Chronological **team overlap is expected**, not proof of test leakage: the model itself uses only minute-available gold and elapsed time, **not** team or league IDs.

## Original-cohort data and method

This follow-up starts with [the 500-game original split manifest](../research/frozen_original_split_manifest.csv), the saved [3,836 TEST predictions](../artifacts/heldout_predictions.csv), and a [500-row match-to-group identity extract](../research/frozen_cohort_group_metadata.csv). The last file is generated by the included [read-only metadata extraction and audit script](../research/team_league_dependency_audit.py) from the author's original 500 cached OpenDota `/matches/{id}` payloads. It holds *match ID, start time, patch, original partition/series, league ID and two team IDs*, **not** raw gameplay, outcomes or any feature/model input. One original TRAIN raw payload had `series_id: null`; the original manifest's established zero/unknown convention is retained, rather than inventing a series. No new OpenDota calls are necessary to **reproduce this audit** using the bundled identity extract; the underlying raw payload cache is **not shipped**, so its initial provenance is not independently verifiable from the ZIP alone.

The script verifies every match/partition against the original manifest and fails if the frozen TEST CSV SHA256 differs from `03b4f6d67e7cb5b7af8097be145fc8cfdd510beefbe85e052bb0445ba7a0c441`. It independently recomputes paired log loss/Brier for each minute row, aggregates loss sums by *entire match* or *entire series*, samples clusters with replacement (30,000 draws, fixed seed 20261116), and divides summed loss by summed row counts to preserve the notebook's minute-weighted estimand. It also deletes one whole league at a time **without refitting** as an influence diagnostic. Group-level analyses are descriptive, **not model-selection gates**.

## Independently reproduced findings

| Fixed TEST feature | Result |
| --- | ---: |
| Games / minute opportunities | **106 / 3,836** |
| Distinct positive series | **54** |
| Leagues / distinct recorded team IDs | **9 / 65** |
| TEST team IDs also seen in TRAIN | **52 / 65 (80.0%)** |
| TEST team IDs also seen in VALIDATION | **46 / 65 (70.8%)** |
| Games in the top two TEST leagues | **49 / 106 (46.2%)** |
| Frozen M1 − M0 log-loss point difference | **−0.012430** |
| Frozen M1 − M0 Brier point difference | **−0.003559** |

Both aggregate point estimates favor M1, **without claiming inferential superiority**.

| Resampling unit | Clusters | M1−M0 log loss: post-hoc percentile 95% interval | M1−M0 Brier: post-hoc percentile 95% interval |
| --- | ---: | ---: | ---: |
| Whole match | 106 | **[−0.03017, +0.00131]** | **[−0.00706, +0.00011]** |
| Whole series | 54 | **[−0.02825, +0.00009]** | **[−0.00662, −0.00041]** |

The log-loss intervals **include zero for both grouping levels**; match-level Brier does too. Series-level Brier lies narrowly below zero, illustrating **sensitivity to the chosen resampling unit**, not independent validation. Separate series can share two teams or league-specific shocks, so even resampling 54 series does **not** guarantee independence.

A leave-one-league-out **point-estimate** diagnostic keeps log-loss Δ below zero for each of nine omissions, ranging approximately **−0.01598 to −0.00759**. However, the eight games in league ID **17909** alone show **positive Δlogloss +0.02852**, indicating heterogeneity rather than a uniform treatment effect. This is **post-hoc inspection of the same TEST**. With nine nonrandom and uneven leagues, **do not present a naive nine-cluster percentile interval as a valid confidence interval**. Team-level cluster resampling would also be nontrivial because each match belongs to *two* teams.

## Scientific interpretation and what changes

**No original scoring metric, selection rule, source feature, game, label, split or forecast changes.** Keep the current report's M0 reference / M1 shadow-only decision. The realistic deployment target is later games in a similar patch/league mixture where teams are often familiar; this dataset cannot establish transportability to unseen teams, unseen leagues or a future patch. One league can hurt while the pooled point estimate improves.

To make a **stronger future** claim, freeze a later multi-league cohort **before** outcome inspection, define estimands by match/series/time horizon in advance, log true feed received-at and label-maturity timestamps, and report calibration/proper scores with dependence-aware uncertainty and sensitivity to league/time. For the present seven-day take-home, further fitting or choosing features on opened TEST would **reduce** credibility rather than raise it.

## Reproduce offline on BigLinux or any Python environment

```bash
python -m pip install -r requirements.txt
python research/team_league_dependency_audit.py
python -m unittest discover -s tests -p 'test_*.py' -q
```

To regenerate the *metadata extract* from an already existing author-owned 500-file OpenDota parsed JSON cache (not part of the reviewer delivery):

```bash
python research/team_league_dependency_audit.py --build-metadata-from-cache /path/to/vexil_opendota_json_v1
```

The script **never** calls the OpenDota API, fits a model, uses team/league IDs in predictions or modifies the frozen TEST. The source digest, numeric results and caveats are machine-readable in [the committed receipt](TEAM_LEAGUE_DEPENDENCE_RECEIPT.json).
